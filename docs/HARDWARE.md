# Стенд ESP32-S3-WROOM-1 N16R8

Это конфигурация нового модуля ESP32-S3, а не заводского одноядерного ESP32-for-Haier. Нужны питание3.3V, общая земля, цепь EN/BOOT и UART-программатор с логикой3.3V. Модуль не имеет входа5V; схему питания сверяйте с [Espressif](https://docs.espressif.com/projects/esp-hardware-design-guidelines/en/latest/esp32s3/schematic-checklist.html).

| Назначение | Вывод ESP32-S3 | Подключение |
|---|---|---|
| UART0 TX | GPIO43 / TXD0 | RX программатора ESP Link |
| UART0 RX | GPIO44 / RXD0 | TX программатора ESP Link |
| hOn TX | GPIO17 | RX платы кондиционера |
| hOn RX | GPIO18 | TX платы кондиционера |
| RS485 TX | GPIO15 | DI трансивера |
| RS485 RX | GPIO16 | RO трансивера |
| RS485 direction | GPIO21 | DE и /RE вместе, подтяжка10k кGND |
| GND | GND | Общая сигнальная земля по схеме питания/изоляции |

Выводы заданы substitutions в haier-s3.yaml. UART0 зарезервирован под прошивку/логи, остальные два аппаратных UART выделяются ESPHome двум UART-компонентам. GPIO35..37 у N16R8 заняты PSRAM и не используются. GPIO0/45/46 не используются для шины.

Трансивер должен иметь совместимые3.3V уровни (например3.3V RS485-трансивер); голый5V MAX485 нельзя напрямую подключать выходомRO к ESP32. MAX485ESA USB-адаптер может служить клиентской стороной RS485 без переделки. Терминация и смещение шины выбираются для фактической линии; это не законченный проект промышленной защиты/изоляции.

На DE предусмотрите аппаратную подтяжку кGND, чтобы передатчик молчал при reset/boot. ESPHome flow_control_pin использует штатный UART RS485 half-duplex driver. Отключённый RTU не передаёт ответы. Питание модуля и изоляцию относительно силовой платы проверяют до подключения USB/компьютера.

Сначала запускайте отдельно от кондиционера: chip/flash/security read, прошивка S3-образа, AP/web/OTA. Затем подключайте hOn, после — RS485. Аппаратные тесты новой платы ещё не выполнены.

## Зафиксировано для будущей схемы — v0.6.0

Назначение GPIO согласовано 2026-09-20. Номера выше — GPIO, не порядковые номера площадок модуля. Не менять их при разводке без одновременного изменения прошивки.

- Первый этап: разъём Haier с TX от GPIO17, RX к GPIO18 и GND. Интерфейс 9600 бод, 8N1. TX контроллера соединяется с RX кондиционера, RX контроллера — с TX кондиционера. Порядок физических контактов разъёма ещё не зафиксирован.
- Второй этап: RS-485 на GPIO15/16/21, по умолчанию 19200 бод, 8N1. MAX485 обсуждался как вариант; конкретный трансивер и согласование уровней ещё не выбраны. Это резервирование сигналов, не готовая электрическая схема.
- UART0 GPIO43/44 остаётся доступным для прошивки и журналов (115200 бод).
- Питание модуля — 3.3 В. Источник питания, стабилизатор, защита и распиновка разъёма питания должны быть определены при разработке схемы отдельно.

На новой тестовой плате подтверждены запуск v0.6.0, Wi-Fi, flash 16 МБ и определение PSRAM 8 МБ. На момент фиксации разъём Haier ещё не распаян; связь с кондиционером и RS-485 на этой плате не проверены. Адрес и MAC конкретного стенда сохранены только в private/PAUSE-2026-09-20.md.

Диагностическая сборка 0.6.1: включена внутренняя pull-up на Haier RX GPIO18; TX GPIO17 остаётся обычным выходом без подтяжки. На рабочей ESP8266 GPIO5 TX/GPIO4 RX — программный UART, обе подтяжки выключены; формат и буфер совпадают (9600 8N1, 512 байт). Эксперимент отменён пользователем до установки. Действующая конфигурация восстановлена: GPIO18 без подтяжки, как на ESP8266. Пробный образ 0.6.1 не использовать.
