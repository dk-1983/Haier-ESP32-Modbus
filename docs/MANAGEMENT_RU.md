# Пароли и обновления GitHub

## Пароли

Откройте `/settings` после входа под `admin`. Пароли web, ArduinoOTA и точки настройки меняются независимо; пустое поле сохраняет текущее значение. Web/OTA: 16–64 печатных ASCII-символа без пробелов, AP: 8–63. После ответа на сохранение контроллер перезапускается; подключитесь с новым паролем. API не возвращает сохранённые пароли. Сброс Wi-Fi их не удаляет.

Новая публичная установка допускает первичную настройку только через AP (`Haier-Setup`). До подключения к сети нужно задать все три личных пароля. Начальный пароль AP даёт доступ к назначению реквизитов, но не является паролем администратора. Общего web/OTA-пароля нет. Сохранённые реквизиты NVS всегда имеют приоритет. Для переноса встроенных паролей v1.0.0 сначала устанавливается приватная миграционная сборка; затем — публичный образ. Миграционный бинарник не публикуется. Забытые реквизиты требуют последовательного порта для восстановления; полное стирание Flash удаляет также Wi-Fi/MQTT/Modbus.

## Обновления

На `/updates` есть сохраняемый выключатель установки, в том числе кнопки Install. Check только проверяет метаданные; для ручной установки разрешите обновления и нажмите Install. Автопроверка начинается примерно через минуту, затем каждые шесть часов с небольшим случайным сдвигом. При запрете метаданные всё равно проверяются. Выключение отменяет текущую загрузку до выбора загрузочного раздела; уже принятое решение о перезапуске отменить нельзя.

Используется только `releases/stable.json` из main нашего GitHub. Точная строка payload подписывается отдельным ключом ECDSA P-256, в прошивке только открытый ключ. HTTPS проверяет сертификаты и имена узлов, включая переходы на CDN GitHub. Проверяются профиль `haier-s3-n16r8-v1`, числовая стабильная версия, размер, SHA-256 и заголовок приложения ESP32-S3. Factory-файлы, другой профиль, старые/равные версии и повтор неудачного образа отклоняются. Нужны Интернет и время NTP.

Загрузка работает в отдельной задаче, локальные службы продолжают работать. Ожидается завершение команды кондиционеру, новые записи во время обслуживания блокируются. ArduinoOTA и GitHub используют общую блокировку Flash. Записывается только неактивный раздел; ошибка хеша/образа не переключает загрузку. До выбора кандидата сохраняются предыдущий раздел и признак пробного запуска. Подтверждение — после 45 секунд исправной локальной работы и Wi-Fi. Перезапуск без подтверждения или 120 секунд нездорового запуска приводят к попытке вернуться на прежний раздел.

**Ограничение отката:** загрузчик v1.0.0 не включает автоматический rollback ESP-IDF. Программный возврат требует, чтобы новая программа дошла до инициализации обновлений; более ранний сбой может потребовать восстановления через последовательный порт. Наличие двух разделов само по себе не гарантирует восстановление после любого сбоя. eFuse и загрузчик через OTA не переписываются. Подтверждение запуска не заменяет проверку всех функций кондиционера.

## Подготовка релизов

Публичные образы собираются чистым workflow `Release binaries` с `public_release=true`. После тестов и проверки образов выполните `tools/sign_release.py --build ... --key private/release-signing.pem --out .../stable.json`. Закрытый ключ нужно сохранить в резервной копии вне Git; его нельзя прикладывать к релизу. Открытый ключ сохраняется для следующих обновлений. Бинарники и соответствующие исходники публикуются под тегом версии; подписанный манифест переносится в `releases/stable.json` только после испытаний. Приватный тестовый канал отделён от stable и запрещён в публичных сборках.

Из [4VRS-Display](https://github.com/dk-1983/4VRS-Display) использованы хранение реквизитов NVS, CSRF-защита, подпись манифеста, ограниченный JSON-парсер, полные URL перенаправлений, последовательная запись Flash, сохранение политики и пробный запуск. Отрисовка дисплея, политика HA и его профиль/адреса разделов в контроллер не переносятся.
